客户端导入

客户端导入

每种客户端导入订阅的方式不同，按你用的客户端选一页。

在哪里：订阅 › 你的客户端

订阅页的「你的客户端」一排就是下表的七项，顺序相同。选哪一项决定订阅链接的格式（链接里的 format=）；格式相同的客户端拿到同一份正文。

客户端 格式 适用场景
mihomo / Clash yaml mihomo（Clash.Meta）内核的客户端，导入即是完整配置，支持分流方案。
Stash yaml 与 mihomo 同一份 YAML 正文、同一份分流设置，可一键导入。
Surge surge Surge 5 的完整配置；Surge 不支持的协议自动省略。
sing-box singbox sing-box 的完整配置；完整配置里只有它装得下共享 Snell 节点。
Shadowrocket base64 通用 Base64 订阅，一键导入 Shadowrocket。
NaïveProxy naive NaïveProxy 客户端的原始 config.json，每个 NaïveProxy 节点一份。
通用 / 其他 base64（另有 uri） 任何认订阅链接的客户端；原始 URI 适合逐条复制。

各格式装得下哪些节点

格式装不下的节点不写进正文，订阅页会把它列在「未写入正文」里，原因写明。

节点 yaml surge singbox base64 / uri naive
VLESS 可 不可 可 可 不可
Shadowsocks 可 可 可 可 不可
Snell，每人一份凭据 v5 可，v6 不可 可 可 可 不可
Snell，多人共享凭据 不可 不可 可 可 不可
mieru 可 不可 不可 可 不可
AnyTLS 可，带 REALITY 的不可 可，带 REALITY 的不可 可 可 不可
NaïveProxy 不可 不可 不可 不可 可
SOCKS5 带用户名密码的可 带用户名密码的可 带用户名密码的可 可 不可
WireGuard 隧道 可 可 可 不可 不可

表里的「可」是协议层面的；同一协议的个别传输层组合（例如某些 VLESS 传输层、带插件的 Shadowsocks）某个客户端装不下时，照样记在「未写入正文」里。

注意

  • 订阅链接只对选中的客户端格式成立：换客户端要回订阅页重新复制或重新导入，不要把一个客户端的链接贴进另一个客户端。
  • 一键导入用的是客户端注册的深链接，只在装了该客户端的设备上有效；Surge、NaïveProxy 与「通用 / 其他」没有深链接，复制链接手动添加。
  • 分流方案只对 yaml、surge、singbox 三种格式有效；其余格式的链接固定是节点列表。
