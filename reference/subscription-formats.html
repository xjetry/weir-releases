订阅格式与响应头

订阅格式与响应头

订阅有六种输出格式，响应头告诉客户端用量、到期与名字。

在哪里：用户门户 › 订阅；订阅地址用 format 选择格式，用 client 标识客户端。

格式键 内容 常见客户端
uri 每行一条分享 URI 接受逐行链接的客户端
base64 URI 列表整体编码；未指定格式时也用它 Shadowrocket、通用客户端
yaml 结构化配置 mihomo、Stash
singbox 结构化配置 sing-box
surge 配置文本 Surge
naive NaïveProxy 配置，只含该协议 NaïveProxy
  • client 不能脱离 format 单独使用，两者必须匹配；只有 yaml、singbox、surge 支持 profile 分流方案。
  • 没有可交付节点时，结构化格式仍返回空配置文档，uri 与 base64 返回空正文；这与无效订阅令牌的 404 不同。
  • 下列头描述实际交付内容，省略数只在大于零时出现，不能将三种省略合并成一种故障。
响应头 含义
Content-Type uri、base64、surge 为 text/plain；yaml 为 text/yaml；另两种为 application/json，均带 charset=utf-8
Cache-Control 成功交付为 no-store
Profile-Title base64: 前缀加编码的站点名与方案名；无方案时名称部分用 default
Content-Disposition inline 加清理后的文件名，按格式使用 .txt、.yaml、.json、.conf；必要时附 filename* 保留中文
subscription-userinfo upload=0，download 为计费用量；有上限才写 total，有到期才写 expire。没有有效套餐时省略整头，无限额套餐使总上限省略；到期取账户与有效套餐中最早者
profile-update-interval 客户端更新间隔，单位小时，正值才写
X-Weir-Degraded-Routes 未交付的退化线路数量
X-Weir-Omitted-Lines 格式不能承载或材料不可用而省略的行数
X-Weir-Skipped-Rules 当前客户端不能表达而跳过的分流规则数
  • 拉取过快时返回 429，并写 Retry-After: 60；有效令牌只在所属站点域名下可用。订阅地址本身就是凭据，不公开转发。
