线路

线路页管端口转发与链式代理两族线路实例，以及可复用的组合线路。

在哪里：网络 › 线路

怎么用

  1. 在线路实例页签按用户、形态与搜索词找到目标行，先区分端口转发和链式代理。
  2. 点新建规则为用户创建端口转发；链式代理在控制台只作查看与排障。
  3. 需要复用多跳路径时切换组合线路页签，维护成员与经过方式。
  4. 修改路径后返回实例表，逐跳确认扣发、应用态与出口状态，而不只看定义保存成功。

字段

字段 必填 默认 说明
用户 user_id 新建规则时是 未选 实例所属用户；管理系统生成的路由需看其所有者。
名称 name 规则可选 空 给规则起显示名，不改变经过路径。
路径 segments 规则是 至少选择一段 每段声明所用授权体及经过方式，不是任意拼接机器。
逐跳结果 hops 只读 按规划与报告 端口转发的实际监听、目标、扣发与应用状态。
链式状态 state / degraded_reason 只读 按当前报告 分别说明进行到哪一步、为什么不能运行。
所有者引用 只读 按生成来源 product_id、rule_id 或 chain_owner_id 指向应当修改的源对象。
形态 shape 只读派生 按路径 纯透传为透明线路；包含协议跳为链式线路，不等于对象族。

注意

  • 线路实例与组合线路不是同一张表：前者是运行对象，后者是可被引用的路径。
  • 同一台服务器以单服务器线路或组合成员身份被使用，授权和计费可能不同；拥有服务器代理不等于拥有单服务器线路。
  • 成品或出口路径生成的托管规则标为面板托管，不能在这里改路径、停用或删除；成品实例只能改监听端口与轮换客户端凭据，其余回到成品修改。由规则派生的链也要回到规则修改。
  • 额度或端口预算导致扣发时，行可继续显示启用。恢复条件后重新装配，不必删除重建。
