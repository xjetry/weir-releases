端口转发

端口转发

端口转发把一台服务器上的一个端口交给下一跳，一直交到目标地址。

在哪里：网络 › 线路 › 线路实例 › 新建规则

怎么用

  1. 在线路实例页点新建规则，先选用户，再按顺序选路径段与每跳经过方式。
  2. 选择落地目标或填写自定义目标；路径有协议跳时必须选可用链尾，不能再填裸目标地址。
  3. 核对 L4 协议、监听端口与高级选项里的连接池大小。表单按草稿预演一次保存，有拒绝时在路径一栏说明原因；对照右侧转发摘要的路径后点创建规则。
  4. 在详情复制实际入口地址，并逐跳检查扣发与应用态；存在告警时规则可能已保存但还不能用。

字段

字段 必填 默认 说明
用户 user_id 是 未选 编辑时锁定，不能借改规则换持有人。
名称 name 否 空 可选显示名。
L4 协议 l4 是 TCP 可选 TCP、UDP、TCP_UDP，仍受各跳能力约束。
路径 segments 是 待选择 至少一段；每段选单服务器线路、组合线路或可用首段隧道线路。
经过方式 via 服务器段是 必须明确选择 透传（内核态）为 KERNEL，透传（用户态）为 USERSPACE，协议为 FACE。
协议面 deployment_id FACE 时是 未选 指定本面板可作为协议跳的部署；透传两档不能同时指定它。
自定义目标 exit_host / exit_port 地址出口时是 空 地址与 1 至 65535 的端口；带链尾时由链尾接管，不能同时填写。
链尾 tail 跨协议跳时是 随目标选择 可以指向允许的部署、成品、链式代理或外部代理身份；直出须满足路径尾部条件。
监听端口 listen_port 否 新建留空自动 零或空在新建时自动分配，编辑时保留当前端口；非零只改第零跳。
连接池大小 pool_size 是 新建为 4 在高级选项里，路径含用户态跳时才显示；非负整数，是用户态跳预连下一跳的数量，0 明确关闭预连接。
转发方式 effective_exit_mode 只读 按实际末跳 来自末跳声明的经过方式，不是全规则的统一模式开关。

注意

  • 内核态与用户态都只是透传，协议跳才会在指定面上重新拨号；位置变化不会把经过方式自动换成另一档。
  • 纯 UDP 规则的每一跳只能走内核态，用户态中转只接 TCP；入口服务器没有 IPv4 地址时首跳不能用内核态，内核转发只接 IPv4。被拒时按提示改对应那一跳的经过方式。
  • 预览不占端口，保存仍会重新规划；交付给用户的是保存后入口地址，不是预览的临时端口。
  • 一连上就先发招呼的目标服务应将连接池设为 0，否则预开连接可能因未认证而被目标关闭。
  • 托管规则回源对象修改。选择链式代理作为链尾会生成规则自己的路由和凭据，不是与原路由共用同一份计量。
