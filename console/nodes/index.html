节点

节点

节点页管客户端能连的每一条协议线：协议配置、部署到哪台服务器、以及隧道。

在哪里：网络 › 节点

怎么用

  1. 在节点页按种类、归属、来源、服务器或用途筛选，打开目标行查看状态。
  2. 新建节点时选协议、填写协议配置，再选服务器与监听端口；保存后逐台检查部署结果。
  3. 复用已有参数时进入协议配置页签，找到原配置后继续部署，不必重复新建。
  4. 成品节点、公共节点从本页对应按钮新建或导入；隧道在独立页签管理。

字段

字段 必填 默认 说明
名称 name 创建协议配置时是 空 协议配置的显示名称；不是服务器名称。
协议配置 inbound_id 部署时是 所选配置 保存参数本身不会在机器上建立监听。
服务器 node_id 部署时是 所选服务器 一份协议配置可部署到多台服务器，每次部署产生一个节点。
监听端口 listen_port 否 配置默认端口预填 可修改；清空由面板从可用端口池分配。
用途 purpose 部署时选择 PUBLIC 部署的属性：可售用途 PUBLIC 或专用落地用途 DEDICATED，部署建好后不能更改。能建接入转发的账户才看到此项，其余按可售用途部署。
订阅可见性 sub_visible 否 新建开启 协议配置的展示开关；不代替用户授权和服务器能力判定。
状态 只读 当前报告 部署行同时看扣发与应用态，不能只看是否启用。

节点表的种类描述直连、中转、链式、中转链式或隧道；属性描述可直连、可落地；归属描述自有或公共。这几条轴互不替代。

注意

  • 协议配置不属于某台机器；改同一份配置会影响它名下的部署。
  • 专用落地用途不由套餐、分销商共享或联邦导出发售；需要改变用途时不能只改订阅可见性。
  • 成品、公共节点池与隧道的操作入口受平台管理权限约束；列表缺少相关查询权限时，不应把未知种类当作直连。
  • 节点启用不等于已经能连。证书、内核或机器应用失败仍可能让监听缺席。
